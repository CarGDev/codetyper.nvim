1. INTRODUCTION                                    *codetyper-introduction*

Codetyper.nvim is an AI coding partner that builds bounded prompts from a
selection, cursor position, or inline tag and applies reviewable edits.

Features:

- selection and cursor transforms with conflict review
- explain and question prompts in a markdown window
- FILE:CREATE, FILE:MODIFY, and FILE:DELETE agent operations
- six bounded project-agent tools
- CodeGraph, TokenSave, and Context7 context adapters
- safe deterministic imports and a selectable ask-user popup
- Copilot, Ollama, Claude, and ChatGPT Plus/Pro provider routing
- scope-aware context, indexing, queueing, and cost tracking

==============================================================================
2. REQUIREMENTS                                    *codetyper-requirements*

- Neovim 0.9 or newer
- curl for HTTP providers and the Context7 fallback
- At least one configured provider: Copilot, Ollama, Claude, or OpenAI
- Optional nvim-treesitter for richer scope resolution
- Optional mcphub.nvim, CodeGraph, and TokenSave for context tools

Tests do not require providers, credentials, external binaries, MCPHub,
databases, or network access. They use headless Neovim and injected fakes.

3. INSTALLATION                                    *codetyper-installation*

Using lazy.nvim: >lua

  {
    "cargdev/codetyper.nvim",
    config = function()
      require("codetyper").setup({
        llm = { provider = "copilot" },
      })
    end,
  }
<

Using packer.nvim: >lua

  use({
    "cargdev/codetyper.nvim",
    config = function()
      require("codetyper").setup()
    end,
  })
<

4. CONFIGURATION                                  *codetyper-configuration*

The supported provider names are exactly |codetyper-providers|:
`copilot`, `ollama`, `claude`, and `openai`.

Example configuration: >lua

  require("codetyper").setup({
    llm = {
      provider = "copilot",
      smart_selection = false,
      copilot = {
        model = "claude-sonnet-5",
        ask_model = "gpt-5-mini",
      },
      ollama = {
        host = "http://localhost:11434",
        model = "gemma4:26b",
      },
      claude = {
        model = "claude-sonnet-4-5",
        ask_model = "claude-3-5-haiku-20241022",
      },
      openai = {
        model = "gpt-5.5",
        ask_model = "gpt-5.4-mini",
      },
    },
    patterns = {
      open_tag = "/@",
      close_tag = "@/",
      file_pattern = "*.codetyper.*",
    },
    keymaps = {
      transform = "<leader>ctt",
      model = "<leader>ctm",
      terminal = "<leader>ter",
    },
  })
<

Configuration rejects unsupported providers, malformed provider blocks, and
non-canonical companion patterns. Explicit provider/model choices remain
authoritative. Automatic resolution checks authenticated Copilot first and
uses reachable Ollama only as a fallback.

Provider and model metadata is stored in
`~/.local/share/nvim/codetyper/configuration.json`. Secret values are scrubbed
from persisted metadata. The canonical companion for `src/app.lua` is
`src/app.codetyper.lua`; legacy `name.codetyper/<extension>` directories are
left untouched.

5. PROVIDERS                                        *codetyper-providers*

GitHub Copilot~
                                                    *codetyper-copilot*
Copilot uses OAuth exchange credentials from Copilot integrations or the
Codetyper device flow. `:CoderAuth` validates existing authentication before
starting a new flow. Model discovery is provider-specific and cancellable.

Ollama~
                                                      *codetyper-ollama*
Ollama is a local HTTP provider. It can be selected explicitly or used as the
automatic fallback when Copilot authentication is unavailable.

Anthropic Claude~
                                                      *codetyper-claude*
Claude reads only the inherited `ANTHROPIC_API_KEY`. The value is sent in
memory as `x-api-key` and never persisted. Generation is non-streaming and
does not expose native tools. An absent key makes Claude unavailable.

ChatGPT Plus/Pro~
                                                     *codetyper-openai*
The `openai` provider uses ChatGPT subscription OAuth, not `OPENAI_API_KEY`.
Authenticate with: >

  :Coder auth openai browser
  :Coder auth openai device
<
OAuth tokens, account identity, residency, and request headers remain in
memory. Restarting Neovim requires re-authentication; only the selected model
preference may be stored.

6. COMMANDS                                          *codetyper-commands*

`:Coder` is the main dispatcher. It accepts:

  version                 Show the plugin version
  reset                   Reset processed prompts
  transform-selection     Open the transform prompt
  index-project           Index the project
  index-status            Show project index status
  llm-stats               Show accuracy statistics
  llm-reset-stats         Reset accuracy statistics
  cost                    Toggle the cost window
  cost-clear              Clear session cost tracking
  terminal                Toggle the terminal window
  queue                   Toggle the prompt queue
  autotrigger             Toggle automatic /@ @/ processing
  process                 Process /@ @/ tags in the current buffer
  credentials             Show provider credential status
  switch-provider         Switch the active provider
  model [provider/model]  Select a provider-labelled model
  auth                    Authenticate Copilot
  auth openai browser     Authenticate ChatGPT with browser OAuth
  auth openai device      Authenticate ChatGPT headlessly

Standalone commands include `:CoderTransformSelection`, `:CoderIndexProject`,
`:CoderIndexStatus`, `:CoderCost`, `:CoderCredentials`,
`:CoderSwitchProvider`, `:CoderModel`, `:CoderAuth`, `:CoderAutotrigger`, and
`:CoderProcess`.

7. WORKFLOW                                          *codetyper-workflow*

Transform selection~

1. Select code or place the cursor.
2. Press `<leader>ctt`.
3. Describe the change and submit with `<CR>`.
4. Review and resolve the generated conflict.

Normal mode inserts at the cursor. Visual mode replaces the selected range.
`<Esc>` or `q` cancels an open prompt window.

Inline prompts~

Write tags inside comments: >

  -- /@ add input validation to this function @/
<

`:CoderProcess` handles tags manually. `:CoderAutotrigger` toggles automatic
processing. Multiple tags are processed sequentially.

Scope and context~

Codetyper uses Tree-sitter when available and indentation fallback otherwise.
Partial function selections include their enclosing function as context while
only the requested range is applied. Explain prompts use the explanation
window rather than silently applying generated code.

8. AGENT TOOLS                                      *codetyper-agent-tools*

The registry owns exactly six canonical tools:

  codegraph_context(query,max_nodes,no_code)
  tokensave_search(query,limit)
  context7_resolve_library(query)
  context7_query_docs(library_id,query)
  ask_user(question,options)
  add_import(path,statement)

Native structured calls and text markers share bounded validation and the
result shape `{status,data,error,stale}`. Encoded results are limited to 4000
characters.

CodeGraph~
                                                    *codetyper-codegraph*
The adapter checks `codegraph` and runs status before read-only `context` or
`explore` calls. It uses fixed argv, bounded output, and an absolute project
root. Uninitialized projects are unavailable; pending, indexing, or stale
indexes return stale results. It never runs `init`, `sync`, `index`, `daemon`,
or database operations.

TokenSave~
                                                    *codetyper-tokensave*
The adapter requires `.tokensave/config.json`, branch metadata, a mapped
current Git branch, and ready status. It runs only read-only status and search
commands. It accepts bare JSON and the `content[].text` double-encoded JSON
envelope. Unmapped branches and stale indexes fail closed; the adapter never
opens a TokenSave database.

Context7~
                                                      *codetyper-context7*
MCPHub is tried first under the `context7` alias. The fallback uses only
`https://mcp.context7.com/mcp`, retains `Mcp-Session-Id`, accepts JSON/SSE,
supports cancellation, and allowlists `resolve-library-id` and `query-docs`.
`CONTEXT7_API_KEY` is read in memory only. URLs, headers, sessions, payloads,
and credentials are not persisted in result metadata.

Ask-user popup~
                                                   *codetyper-ask-user*
The popup accepts one question and at most eight non-empty options. Use
`<Up>`/`<Down>` and `<CR>` to select, or `<Esc>` to cancel. Interactive and
mutating requests are FIFO-serialized and callbacks complete exactly once.

Safe imports~
                                                    *codetyper-add-import*
`add_import` supports JavaScript/TypeScript, Python, Lua, Go, Rust, C/C++,
Java/Kotlin, Ruby, and PHP. It preserves headers, package/namespace metadata,
line endings, and unsaved buffer content. Traversal, absolute paths,
documentation files, remote references, multiline declarations, unsupported
languages, and ambiguous declarations are rejected without mutation.

Native and marker dispatch~
                                                   *codetyper-tool-dispatch*
Native schemas are sent only to eligible tool-capable Copilot project tasks.
Claude, OpenAI, and Ollama receive no native schemas. Text markers are:

  TOOL:CODEGRAPH {"query":"request","max_nodes":20}
  TOOL:TOKENSAVE {"query":"request","limit":10}
  TOOL:CONTEXT7_RESOLVE {"query":"neovim"}
  TOOL:CONTEXT7_QUERY {"library_id":"/neovim/neovim","query":"autocmd"}
  TOOL:ASK_USER {"question":"Continue?","options":["Yes","No"]}
  TOOL:ADD_IMPORT {"path":"lua/app.lua","statement":"local M = {}"}

Malformed, array-shaped, unknown, and double-encoded payloads are rejected
before execution. Local tools run before external MCP calls. Terminal calls
remain a separate visible boundary with dangerous command patterns blocked;
filesystem and shell MCP tools are excluded from the native API surface.

9. SAFETY                                            *codetyper-safety*

- HTTP uses argv-only curl, temporary request bodies, bounded output, and
  cleanup on completion or cancellation.
- CLI adapters use argv arrays, fixed command shapes, status checks, bounded
  stdout/stderr, and safe diagnostics.
- Tool paths, arguments, result sizes, and tool names are validated before
  side effects.
- Provider credentials and OAuth state are not included in prompts or saved
  project metadata.
- Missing, stale, malformed, cancelled, and timed-out integrations fail
  closed and suppress late callbacks.

See `SECURITY.md` in the repository for private vulnerability reporting.

10. KEYMAPS                                         *codetyper-keymaps*

Default mappings:

  <leader>ctt    Normal/Visual    Open transform prompt
  <leader>ctm    Normal           Select a provider-labelled model
  <leader>ter    Normal           Toggle terminal

Mappings are configured under `keymaps`. Set one to `false` to disable only
that mapping: >lua

  keymaps = {
    model = "<leader>cm",
    terminal = false,
  }
<

Conflict review mappings:

  co             Keep current code
  ct             Accept incoming code
  cb             Keep both versions
  cn             Accept neither version
  cm             Open the conflict menu
  ]x / [x        Next/previous conflict

==============================================================================
11. TESTING                                         *codetyper-testing*

The headless Plenary suite uses injected network, CLI, MCPHub, provider,
buffer, popup, and cancellation fakes. It does not require network access,
credentials, CodeGraph, TokenSave, an MCP server, or a database.

Run: >

  make test
  make test-file FILE=tests/spec/context7_spec.lua
  make lint
  make format-check
  make docs
<

Boundary tests cover fixed argv, secret cleanup, malformed and double JSON,
stale indexes, path/shell/tool allowlists, cancellation, popup lifecycle,
native/marker parity, unsupported providers, and no-mutation failures.
